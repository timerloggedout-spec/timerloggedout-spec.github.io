## Usage

1. Start with the relevant page in the sitemap or the llms.txt index.
2. Prefer Markdown mirrors when present; otherwise parse the page's static HTML.
3. Follow links to GitHub for canonical code, issues, pull requests, releases, and workflow evidence.
4. Treat dashboards as derived projections. Check their generated-at timestamps and source links before relying on values.
5. Preserve status distinctions: proposed, implemented, committed, executed, validated, and promoted are different states.
6. If a source is missing, stale, or inaccessible, state that limitation instead of inferring a result.
7. Cite exact repository paths, commit identifiers, pull requests, or evidence artifacts when reporting implementation status.
8. Never copy credentials, private telemetry, or personal information into public files, logs, or comments.
